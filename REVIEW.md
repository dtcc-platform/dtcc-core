# REVIEW.md

Priorities for anyone reviewing a pull request in this repository, human or
agent. Keep it short: when reviewers keep flagging the same thing, turn it into
a Ruff rule or a test instead of a line here.

## What failure looks like here

- A function exported in an `__all__` changes signature or behaviour without
  the PR saying so; the other DTCC repositories build on this one.
- Geometry that is wrong but valid-looking: wrong CRS or units, non-watertight
  shells, flipped face orientation.
- Files written today that cannot be read tomorrow: `dtcc.proto`, CityJSON
  writers or dataset package formats changed without a round-trip test.
- A slower `import dtcc_core`: heavy third-party imports at module level
  (`tests/test_import_time.py` guards this).
- Tests that need network or real provider data running by default; they stay
  opt-in through `DTCC_RUN_DEMOS` and the quick-benchmark workflow.

## Ignore

- `dtcc_core/cpp/external/` and `licenses/`: vendored Eigen, earcut, nanoflann
  and Triangle.
- `dtcc_core/model/dtcc_pb2.py`: generated by `scripts/build_proto`; review
  `dtcc_core/schemas/dtcc.proto` instead.
- `uv.lock`: review the `pyproject.toml` change that produced it.
- `sandbox/`: scratch code, excluded from Ruff.

## How to review

- Review agent-written and human-written changes to the same depth.
- Check the diff against the PR's stated intent and the surrounding code: the
  change does what it claims, follows the codebase's existing patterns, and
  leaves callers working.
- For a bug fix, confirm the root cause is fixed. A patch over a symptom is a
  finding.
- A weakened, skipped, or deleted check is a finding, including a new entry
  under `[tool.ruff.lint.per-file-ignores]`.
- Leave style and cleanup to Ruff; report bugs.

## How to report

- Each finding once, with file and line, labelled important or nit; label code
  the PR did not introduce as pre-existing.
- End with the finding count, or "no issues".
- On a re-review, start from the commits added since your last review and
  review them the same way.
